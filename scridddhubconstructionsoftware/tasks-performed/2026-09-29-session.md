## Decisions (and why)
- **Stricter locating: a missing point beats a wrong one.** "Thane" alone now finds nothing,
  where before it found the district centre ~25 km off. Distances from wrong points mislead
  users; a missing point only means that part of the line isn't measured.
- **Statuses are not set from general knowledge.** Metro Line 7 and the Bandra–Worli Sea Link
  are left pending instead of being marked "open" by hand; stored values must come from a page.

## Problems hit and fixes
- **The 28 Sep scheduled run died in 3 s with nothing logged.** `$ErrorActionPreference =
  "Stop"` in Windows PowerShell 5.1 turns any stderr line from a native program into a fatal
  error. Docker was down (stderr), and the pipeline logs to stderr, so it would have died even
  with Docker up. Fixed in `scripts/run_infra_pipeline.ps1`:
  - Native steps check exit codes; a trap logs anything unexpected.
  - The log is written in UTF-8 (it was UTF-16).
  - Docker Desktop starts from its real path.
- **Locator put Gujarat stations and outside places inside Mumbai.** "Sabarmati" and "Anand"
  matched buildings; "Ahmedabad" matched the bullet-train line itself; "Eastern Express
  Highway" landed at CST. Bad points were removed by hand, then fixed at the root (above).
